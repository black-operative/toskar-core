# Toskar Code of Conduct

## Our Commitment

We are committed to making participation in the Toskar community a welcoming, respectful, and productive experience for everyone, regardless of experience level, background, identity, or circumstance.

Toskar is built around experimentation, collaboration, and making local AI accessible across a wide range of hardware and platforms. We welcome developers, testers, documentation contributors, hardware enthusiasts, researchers, and users of all experience levels.

Participation in this project should be constructive, professional, and respectful.

## Expected Behavior

Examples of behavior that contributes to a positive community include:

- Being respectful of differing viewpoints, experiences, and technical approaches.
- Giving and receiving constructive technical feedback.
- Focusing criticism on code, design, behavior, or ideas rather than individuals.
- Being patient with new contributors and users.
- Helping others reproduce and understand technical problems.
- Clearly distinguishing confirmed facts from assumptions or speculation.
- Respecting privacy and avoiding the publication of another person's private information.
- Accepting reasonable maintainer decisions, even when you disagree with them.
- Taking responsibility for mistakes and correcting them constructively.

Technical disagreement is expected and encouraged. Personal hostility is not.

## Unacceptable Behavior

Examples of unacceptable behavior include:

- Harassment, threats, intimidation, or discrimination.
- Personal insults or attacks.
- Trolling or deliberately inflammatory behavior.
- Repeatedly disrupting technical discussions.
- Sexualized language, imagery, or unwanted sexual attention.
- Publishing private or personally identifying information without permission.
- Deliberately submitting malicious code, malware, credential-stealing functionality, or other harmful contributions.
- Knowingly providing fabricated benchmarks, hardware results, bug reports, or security information.
- Attempting to pressure, threaten, or harass maintainers into accepting a contribution or feature.
- Using project spaces primarily to promote unrelated products, services, political campaigns, or spam.
- Any conduct that would reasonably be considered inappropriate in a professional open-source community.

## Technical Discussions

Toskar deals with operating systems, AI models, hardware, networking, model runtimes, performance, and other areas where reasonable technical disagreements are common.

Contributors are encouraged to challenge ideas.

For example:

> "I don't think this scheduler design handles node failure correctly because..."

is welcome.

Statements such as:

> "Anyone who designed this is an idiot."

are not.

Whenever possible, support technical claims with:

- reproducible tests;
- logs;
- benchmarks;
- documentation;
- source references;
- specific hardware or software configurations.

Maintainers may close discussions that have stopped producing useful technical information.

## AI-Generated Contributions

Using AI tools to assist with contributions is allowed.

Contributors remain responsible for everything they submit, regardless of whether it was written manually or generated with an AI system.

Before submitting AI-assisted work, contributors should verify that:

- the code works;
- tests pass;
- the contribution does what it claims;
- licensing and copyright requirements are satisfied;
- generated code does not introduce secrets or private information;
- generated documentation is factually accurate;
- dependencies or APIs referenced actually exist.

Submitting large amounts of unreviewed AI-generated code or issue content may be treated as spam.

## Security Research

Good-faith security research is welcome and valuable.

Do not publicly disclose an exploitable vulnerability before maintainers have had a reasonable opportunity to investigate and address it.

Security vulnerabilities should be reported using the process described in `SECURITY.md`.

Attempts to exploit other users, access systems without authorization, expose credentials, or intentionally damage Toskar installations are not considered good-faith research.

## Project Spaces

This Code of Conduct applies to official Toskar community spaces, including:

- GitHub Issues;
- GitHub Discussions;
- pull requests;
- code review;
- project documentation;
- official community channels;
- other spaces operated by the project.

It may also apply when someone is publicly representing the Toskar project or community.

## Enforcement

Project maintainers are responsible for interpreting and enforcing this Code of Conduct.

Maintainers may take actions including:

1. Providing a private or public warning.
2. Removing or editing inappropriate comments or content.
3. Locking or closing discussions.
4. Rejecting or closing contributions.
5. Temporarily restricting participation.
6. Permanently banning an individual from project spaces.

Enforcement decisions should consider the severity, frequency, context, and impact of the behavior.

Maintainers should make reasonable efforts to apply these standards consistently.

## Reporting a Problem

If you experience or observe behavior that violates this Code of Conduct, please report it privately to:

**conduct@yeix.io**

Please do not file public GitHub issues for Code of Conduct complaints involving harassment, personal information, or other sensitive matters.

When possible, include:

- a description of what happened;
- where the incident occurred;
- links, screenshots, or other relevant context;
- the people involved;
- whether the behavior is ongoing;
- any immediate safety or privacy concerns.

Reports will be reviewed as promptly and discreetly as reasonably possible.

Information about a report will be shared only with people who need it in order to investigate or respond appropriately.

Anyone handling a report should disclose and avoid conflicts of interest where practical. If the report involves the person who normally handles Code of Conduct matters, it should be escalated to another appropriate representative of YEIXIO LLC.

Retaliation against someone for making a good-faith report or participating in an investigation is not permitted.

Knowingly false or malicious reports may themselves be considered a violation of this Code of Conduct.

## Scope of Maintainer Authority

Maintainers may make final decisions about:

- contribution acceptance;
- project architecture;
- releases;
- repository organization;
- moderation;
- community participation.

Open-source participation provides an opportunity to contribute and collaborate, but does not guarantee that a proposed change will be accepted.

A technical disagreement or rejected contribution is not, by itself, a Code of Conduct violation.
